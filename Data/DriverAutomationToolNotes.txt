Version 10.2.3
What's New & Fixed
- Security / FIPS Compliance — Package integrity hashing now uses SHA256 instead of MD5, so the tool no longer errors out with "not part of the Windows Platform FIPS validated cryptographic algorithms" on FIPS-enforced hosts. Where an OEM catalog only publishes an MD5 hash, verification now degrades gracefully to Authenticode/HTTPS trust rather than failing the download. (#900)
- BIOS Management — Fixed BIOS package detection that failed during a live ConfigMgr task sequence while working correctly in debug mode. Matching previously relied on a value only populated in debug, which broke SystemSKU-to-model fallback — most visibly on Lenovo, where the SKU is only the 4-character machine type. (#902)
- Driver Packaging (Acer) — Disabled the nested cabinet self-expansion that deepened the folder tree on every pass, a primary cause of MAX_PATH overflow and near-empty output WIMs on Acer driver packages.
- UI / Usability — Added a long-path advisory: when the selected temporary path exceeds 120 characters and Windows long-path support is off, a warning panel with an "Enable long path support" action is shown to prevent deep driver files from exceeding the 260-character limit.
- UI / Usability — The cleanup results list is now wrapped in a height-capped, internally scrolling panel so a large result set can no longer grow the borderless window off-screen and hide the Close button.

Version 10.2.2
What's New & Fixed
- Intune RBAC Scope Tags — You can now assign one or more RBAC scope tags to the Intune apps the tool creates. Tenants that enforce role-based scope tags previously rejected every new app (creation failed with a "condition not met" error); apps now carry a permitted tag, with the built-in Default tag used automatically when none is selected. Includes a tag picker in Intune Package Options that populates from the connected tenant, plus scheduled/headless support. (#864)
- Automatic Deployment & Assignment Filters — New option to automatically assign freshly built packages to All Devices or a chosen group, applying the matching assignment filter for each package. Fixed a case where an assignment filter's target was never set so the filter wasn't actually applied, and firmed up the per-model filter rule building (including Lenovo baseboard/machine-type matching). (#895, #897)
- AzCopy Upload Engine (Intune) — Optional Microsoft AzCopy engine for uploading package content to Intune instead of the built-in chunked uploader. It self-tunes concurrency for higher throughput on large driver packages, is downloaded and signature-verified automatically on first use, can run hidden or in a visible window, and shows its version/signature status in Package Options. Also improved upload error handling and reporting.
- WIM Engine Reliability — On machines where DISM hangs during initialization (banner shown, then no progress), the tool now prefers the bundled wimlib engine by default and adds a DISM stall/timeout so a stuck capture no longer wedges the whole build indefinitely.
- Model Matching — Feature-Update Gating — Non-Dell driver packages now require the device's Windows feature update (e.g., 24H2 / 25H2) to match the build the pack was created for, preventing a build-specific package from installing on the wrong Windows release. Dell remains major-OS only, and BIOS packages stay OS-agnostic.
- Toast / Teams Notifications — Added a custom header line to the Teams card so teams running multiple tenants into one channel can label each build by customer/tenant. Notifications now report genuinely updated models separately from those skipped because already current, with each model's true outcome shown — a check-only run is no longer misreported as having updated everything. (#842)
- UI / Branding Fixes — The custom branding/image preview no longer shows a stale image served from the framework's cached decode; the file now loads fresh each time. Also improved file-path detection in settings and refined loading behaviour. (#896)
- Build Reliability — A build that fails part-way through now cleans up its working directory and releases file handles correctly, instead of leaving a partial working folder behind. (#816)


Version 10.2.1
What's New & Fixed
- BIOS Management — Fixed the automatic restart after a BIOS update being silently skipped on unattended/Intune devices. The Focus Assist / Do Not Disturb check no longer treats "no interactive user" (the normal state when running as SYSTEM) as a reason to hold back the reboot, so staged BIOS updates now apply as intended while still deferring for users who are genuinely busy or presenting. (#893)
- OEM Support — Reworked HP SoftPaq driver extraction to use HP's current /s /e /f switches so files land in the build folder instead of the default SWSetup location, which previously left the folder empty and failed the build. Older SoftPaqs are handled automatically by retrying the legacy switches, with the 7-Zip fallback retained, and success is now judged by the files actually produced rather than the installer's exit code. (#892)
- Toast Notifications — Added a Critical Notification (Alarm Mode) option that displays the update prompt even when Focus Assist / Do Not Disturb is active, with an optional audible alarm sound, for forced-reboot or security-critical updates.
- Toast Notifications — Clarified the BIOS "firmware prestaged" message so users know they can restart immediately (or any time before the countdown ends) to speed up the update, alongside the existing warning not to power off during the process.
- Telemetry & Reporting — Added an optional environment profile so administrators can record an approximate device-count range and their primary management platform (Intune, Configuration Manager, Co-Managed, or Standalone). The values are offered during first-run consent and editable in Common Settings, remain optional, and are only included with the end-of-session summary when telemetry is enabled.

Version 10.2.0
What's New & Fixed
- ConfigMgr (Offline) — New Configuration Manager (Offline) platform. Builds and stages driver/BIOS content plus a package manifest to a self-contained export folder on an isolated host, then a bundled Import-CMOfflinePackages.ps1 script lets an admin copy the content to its final destination and create the packages in Configuration Manager on the connected site — no direct site access required from the build machine. (#875)
- XML Logic Package — Now has its own Logic Package menu under ConfigMgr Settings, showing the existing package name and ID with task-sequence integration guidance, plus a scrollable XML Package Contents table (Name, Package ID, Manufacturer, Baseboards, Source Date).
- Download Only — Added a Download Only Options card with an Extract content after download toggle (on by default). Extracted content is staged to a durable \Extracted folder next to the download instead of being left in temp and cleaned away.
- OEM Support — Acer driver packages that ship as a ZIP of nested .cab bundles are now expanded to loose .inf trees before WIM capture, so the package actually contains installable drivers. Guarded so well-formed inf+payload-cab packages are left intact. (#888)
- BIOS Management — Acer BIOS downloads are no longer blocked by a stale catalog hash; a mismatch for Acer is accepted over the enforced HTTPS download instead of hard-failing. Non-Acer OEMs still fail closed on a mismatch with no trusted signature.
- Teams Notifications — A build notification is now sent on every exit path — success, abort, and failure — with an accurate outcome, a "Not Processed" count, and a request timeout so an unreachable webhook can't stall a build. Headless pre-flight failures also notify. (#878)
- UI / Theme Fixes — Added a dedicated accent-text colour so blue links and body text read clearly on dark backgrounds (Replication Priority hyperlinks; curl/wimlib/7-Zip links and paths on Common Settings).
- Documentation — Setup guide and user docs updated for the offline platform, XML logic package, and Download Only options; corrected registry path references across the docs.

Version 10.1.9
What's New & Fixed
- Intune Deployment — New IME Toast Notifications control (Show all / Show reboot only / Hide all) applied to the app assignment. Lets you suppress the Intune Management Extension's own toasts — including its "installation failed" toast shown when a user defers — so only the Driver Automation Tool's toast reaches end users. Applies to newly created or re-assigned packages.
- BIOS Management — Final deferral notice: when a user reaches the maximum number of deferrals, a Focus Assist / Do Not Disturb–bypassing informational toast now always tells them the BIOS update is being pre-staged and will apply on the next restart, with an audible alert. Closes the gap where forced updates could be staged silently.
- BIOS Management — BitLocker protection is now re-verified and re-suspended immediately before the update restart. If protection was re-enabled between the flash and the reboot, the device would previously drop to the BitLocker recovery screen; this prevents that lockout.
- BIOS Management — Cached BIOS binaries whose published catalog hash has drifted (the OEM silently re-released the file under the same URL/version) are now accepted when they carry a valid Authenticode signature from a trusted publisher, rather than re-downloading every run or hard-failing. Still fails closed when the signature is missing or the signer is untrusted.
- Intune Packaging — Hardened content upload: each attempt starts a fresh content version (no partial blobs carried over), access-token expiry during long uploads is handled, and the committed content version is verified after publish. Content-less failed apps are removed so they aren't treated as existing/skippable or offered to devices.
- Reporting & Diagnostics — Per-model applicability and deferral-reason logging is written to the registry, so custom reporting can see why a device is pending or not applicable (user deferral, on battery, awaiting reboot) without parsing IME logs. Reasons are cleared automatically on the next healthy run.
- ConfigMgr Scripts — New multi-package BIOS download/apply script with Lenovo null-fallback handling, exact-token SKU matching, array normalisation, and robust CMTrace logging. The driver apply script gains a documented custom-manufacturer branch, executable output logging, and a graceful fallback when computer data can't be read.
- Remediation Tooling — New maintenance script to clear stale BIOS version markers recorded ahead of the installed firmware, letting devices re-evaluate as "update required" and re-check for their BIOS updates. Includes a no-warranty "use at your own risk" disclaimer.
- User Interface — Added a one-time Bug Notice modal advising that pre-10.1.9 Intune BIOS packages could mis-report the installed BIOS version or trigger a BitLocker prompt, with in-app guidance on clearing the registry markers to force devices to re-check.
- User Interface — The "Packages Created" progress tile now updates live during long All-model builds (instead of appearing stuck on the previous model's count) and resets correctly on headless/scheduled runs.
- Documentation — User guide updated to describe the new IME notification behaviour.

Version 10.1.8
What's New & Fixed
- BIOS Management — BIOS requirement, detection and install now share one manufacturer-aware version comparison (Dell/HP/Surface/Acer compare by version, Lenovo by release date), so a device already on the latest BIOS is no longer wrongly flagged as "update required" when the firmware build date predates the catalogue publish date.
- BIOS Management — During a user's "Remind Me Later" snooze the package now reports Not applicable instead of exiting 1618, so it no longer burns Intune's 3-attempt retry budget; detection is untouched so a device is never falsely shown as installed. (#843)
- OEM Support — Acer BIOS now works end-to-end: discovered, listed and packaged by matching the platform product code, with the Acer XML catalogue kept as an automatic fallback and integrity hashes carried through.
- Intune Package Management — New "Republish Metadata" action refreshes an app's description, information URL, notes and logo in place without re-uploading content, and detection/requirement rule scripts can be regenerated and updated on existing apps in bulk. Metadata was also corrected: proper information URL, notes now record the tool version/build, and the description includes the package release date.
- Download Engine — You can now skip curl entirely and download via .NET HttpClient, with a "Restore Download Engine" control, and downloaded size is verified against Content-Length. (#876)
- Download Engine — The trusted curl SHA-256 pin is normalised (spaces/colons stripped) and persisted correctly. (#809)
- Download Engine — Fixed a case where a stalled download could outlast the timeout guard. (#874)
- Build Experience — The build progress modal now shows live statistics and available disk space with summary tiles, and the model grid keeps selected models sorted to the top. Fixed the build summary inheriting stale counts when all of the current build's models are skipped. (#862)
- Reporting & Diagnostics — Driver and BIOS install scripts are more verbose and write per-device status to the registry (last result, tool/script exit codes, failure phase and message, attempt count); the driver install log is now DriverAutomationTool-Drivers.log, and an INF-level "drivers added" report is produced for patch reporting.
- UI / Theme Fixes — Right-clicking a package row now selects it so single-package actions target the correct row; Assign Package is now a green check and Remove Assignments a red X.

Version 10.1.7
What's New & Fixed
- Lenovo BIOS Cleanup (#863) — Lenovo BIOS updates no longer leave residual C:\SWTOOLS\FLASH and C:\DRIVERS\FLASH folders on the system drive. Because Lenovo's BIOS installers extract to hardcoded system-drive locations regardless of the target path, the build now snapshots those folders beforehand and removes only what the installer newly created (on both success and failure), leaving any pre-existing content untouched.
- Package Retention (ConfigMgr) — Fixed automatic cleanup of superseded packages silently doing nothing. The site code was being read from a status-display field instead of the resolved site connection, producing an invalid WMI namespace so the retention query failed quietly. It now uses the same site globals as every other ConfigMgr operation.
- Intune Applicability — Reworked how driver and BIOS packages decide which devices they apply to. Applicability is now based purely on the hardware identifier (manufacturer + system SKU/baseboard) and OS, with the "is a newer version already installed?" decision moved to the detection rule. This fixes devices on older BIOS/driver versions wrongly showing as Not Applicable, and makes up-to-date devices report as Installed instead of inflating the Not Applicable count.
- BIOS Management — Hardened all BIOS release-date handling. Dates are now parsed culture-invariantly against explicit formats and compared as strict 8-digit values, so a catalog date can no longer be misread on a non-US machine and flip a whole model's fleet to Not Applicable. Null/absent BIOS dates are guarded, and unparseable dates fall back safely to the registry version marker.
- Assignment Filters — Fixed an error when opening the Update / Remove Assignment Filter dialog. Resolved a PowerShell 5.1 incompatibility in the button rendering, gave the dialog its own isolated theme resources, and added clear error reporting so any issue is shown rather than crashing.
- Startup Connectivity Check — Added retry with backoff so a one-off slow endpoint (e.g. Microsoft Graph cold-start) no longer produces a false "connectivity issues" warning. The overlay now shows live retry progress instead of appearing frozen, and a failsafe deadline ensures the check can never hang startup.
- Driver Packaging — The WIM compression level options are now hidden when 7-Zip is selected as the packaging engine, since 7-Zip doesn't support WIM compression.
- Stability — The model search box no longer errors when typing wildcard characters (e.g. [), and unhandled UI exceptions are now written to the log rather than surfaced as raw error text in the status bar.

Version 10.0.43
What's New & Fixed
- Driver Packaging (HP SoftPaqs) — HP driver packages built from individual SoftPaqs are no longer rebuilt on every run. The tool now records the exact SoftPaq list for each model and skips the rebuild when nothing has changed, retaining the existing package and reusing its original version stamp. The log clearly shows the matched SoftPaqs, the comparison fingerprint, and which existing package was retained.
- Driver Packaging (Intune / ConfigMgr) — When deciding whether an unchanged package can be skipped, the tool now verifies the previously created package still exists in the target environment — by Intune application ID or ConfigMgr Package ID — and automatically rebuilds if it was deleted, removing the need to use Force Update to recover.

This applies across the model grid, the build/skip logic, and package metadata, so version-based "skip if current" checks work correctly. - Model Matching — Known-model auto-selection from Intune now matches Dell devices whose reported name includes a "Dell" prefix (e.g. Dell Latitude 5550 now matches the catalog Latitude 5550). A new match summary in the activity log reports how many queried device models matched a catalog entry and lists any unmatched models, making the gap between discovered and selected devices transparent.
- Model Matching (Intune lookup) — Fixed an error ("[System.Int32] does not contain a method named 'Trim'") that could abort the Intune device lookup when a device reported a numeric SKU value via Microsoft Graph.
- Intune Integration — Requirement and detection rule scripts are now uploaded as plain UTF-8 without a byte-order mark, fixing the stray characters that appeared at the top of the script content in the Intune portal.
- Toast Notifications — Fixed rendering of multi-line toast notification text.
- Security / Documentation — Added an API.md reference documenting the telemetry API endpoints, the exact data contained in each payload, what is not collected, and how to opt out — for security/privacy review.
